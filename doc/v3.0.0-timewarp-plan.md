## Order of work

Memory savings and state performance come first. Establish usable, measured
space before adding slowdown, timeline UI or online features.
Do not grow the game's arena reservation to make the feature list fit.

1. Protect the existing timer and establish region/target baselines.
2. Measure actual PPC Quick compression, sharing and transaction peaks,
   including states from different levels. Prove cold-code transport and
   instruction fetch using one unchanged module.
3. Implement and integrate bounded memory savings with existing restore,
   archive, reset and ownership checks. Measure complete saves/loads on all
   three occupied slots; retain fast Quick states where capacity permits.
4. Add Timewarp features within the resulting budgets, with separate proofs
   for each scheduler, state, graphics, format and network change.
5. Package only after compatibility/runtime checks and the user's release
   approval. A private prototype is not a completed release.

### Retained-image compression

Moving an instruction to MEM2 does not remove it from the retained image.
`scripts/timewarp_transport_measure.py` therefore measures a separate boot
transport saving: compress only the two MEM1 initialization payloads, keeping
future executable cold payloads uncompressed. Actual PPC Quick compression
and independent reconstruction of the released bytes produced:

| Region | Original file | Compressed payloads plus old envelope | Gross transport saving |
|---|---:|---:|---:|
| JP | 548,824 | 393,006 | 155,818 |
| US | 542,920 | 388,060 | 154,860 |
| PAL | 542,868 | 388,509 | 154,359 |

Those initial measurements used the runtime PPC encoder. The integrated host
packer now uses a deterministic boot-only LZ4 encoder, with complete V4
descriptor/checksum/alignment overhead included. Hot-only files are JP
376,672 bytes, US 372,320 and PAL 372,416: savings of 172,152 / 170,600 /
170,452 bytes against the released V3 files. All reconstruct the exact
initialized bytes and BSS; V3 output remains byte-identical by default.

`ENABLE_COMPRESSED_MOD` opts into V4 packing. Shared loader/kernel readers
accept V3 and validated console V4. The installer preflights the complete file
before aligned 32-bit MEM1 writes, publishes no hooks itself, and preserves
the attachment/timer gap. Kernel integration publishes hooks only after
installation and extends PPC cache invalidation over the injected hot spans;
a separate checked cold range is invalidated before entry. The retained file
stays immutable for reset. All three compressed console builds and the
launcher build pass. Actual Wii boot/reset remains unverified.

V4 containers containing the consolidated menu cluster also pass installation
and reinjection checks for every region. Their complete console sizes are
JP 404,128 bytes, US 399,712 and PAL 399,616, including cold instructions,
compressed hot payloads, descriptors, checksums and hooks. These are private
relocated builds, separate from the opt-in hot-only CMake builds. The native
installer leaves cold bytes immutable, restores both hot spans and BSS, and
rejects a late damaged block before writing. See
`build/timewarp-mod-v4/consolidated/install-receipt.json`.

Cold bytes must execute uncompressed, so selecting a cold module consumes
some of the transport saving. That saving is space inside the existing
retained-image allocation, not additional state-pool capacity. No arena
reservation grows and no second permanent code copy is introduced.

DOL, Gecko and BPS export paths reject cold manifests until they have a
verified early-copy boot path. The BPS guard prevents silently packing only
the hot segments of an otherwise valid cold build.

### Private block allocator

`include/susamune/state_chunk_pool.h` is the promoted C allocator, not yet
wired into gameplay. Private experiment includes delegate to it. It charges
a 32 KiB directory inside the existing pool, with 1,024
16-byte descriptors and four bounded roots of up to 256 references. The three
published roots and one pending root have direct block IDs, not delta chains.
Each block includes the existing encoded header and stays contiguous within
one physical bank. Alignment and unused bank tails consume capacity.

Hash lookup always checks complete encoded equality. The initial lookup is a
bounded linear descriptor scan; there is no uncharged hash table. It affects
saving, not the direct reference lookup used while reading.

The current Snapshot17 producer/inner validator admits at most 18,075,308 raw
bytes (138 Quick blocks), including game, ghost and practice spans. The generic
archive envelope allows 32 MiB. Supporting 256 references retains the latter
bound without accidentally imposing the initially considered 128-block limit.

Transactions retain every published root while acquiring the candidate's
references. Commit occurs only after the complete candidate and its metadata
are checked under exclusive ownership. Abort releases only the pending
references. A replacement can therefore be refused when its final size would
fit but its temporary peak does not. Do not replace this policy with destructive
reclamation without an independently proved immutable-input allocation plan.

Compaction changes descriptor offsets, not root references. It requires
exclusive ownership: no ARM export, borrowed codec pointer or restore pass may
be active. Interrupted save here means a controlled abort of this in-memory
transaction, not persistent power-failure recovery.

The native C fixture test reconstructs all 15 exact PPC streams, independently
decodes all three states after third-slot publication, and exercises candidate
abort, replacement, forced hash collision, full-pool failure and bank-aware
compaction. Its metadata tags are simulated bindings; full `StoredState`
publication and real gameplay restore remain integration work. Final receipt
and reviewed test counts live under `build/timewarp-state-measure`.

After charging the 32 KiB directory and 32-byte payload alignment, the five
Plaza triples occupy respectively 10,372,768; 10,767,712; 11,429,152;
10,301,728; and 10,197,696 bytes. All fit the current pool in the private
allocator. These figures retain the same Plaza-only limitation as the table.

  `build/timewarp-root-codec/validated/receipt.json`. Full StoredState/gameplay
  integration remains. Keep direct whole-block Quick
  decode into permitted heap ranges and every owner/video/filter exclusion.

  refuse aliasing and callback aborts; incomplete output never reports a

- **Integrity:** bind the ordered root to generation, metadata tag, raw/packed
  sizes and Adler. Check the canonical logical packed CRC before the verified
  writing pass. A deduplication hash is not a substitute for integrity or full
  byte comparison. Preserve late-restore recovery and `COMMIT_FAILED` handling.
- **Storage:** current export passes one linear pool offset to ARM, and import
  writes into a linear pool tail. Neither understands this allocator. Windowed
  import can allocate pending blocks on PPC; export needs a bounded versioned

- **Compatibility:** export Quick using the unchanged canonical header and
  encoded blocks. Preserve existing Deflate archives, initially as checked
  opaque extents if needed. Conversion requires separate source and codec
  workspaces plus transaction capacity; it cannot destroy the recovery copy.
- **Validation:** save three, load each, replace each, export/import, abort,
  corrupt inputs, exhaust capacity, cancel/reset during storage, and replay
  old readers. Measure complete and first-visible-frame loads on Wii as well
  as isolated codec work. A host pass is not a Wii performance result.

## Other MEM2 savings

The 4 MiB state transaction area and `0x13E000` ghost file transfer area are
candidates for a shared transaction buffer, potentially returning 2 MiB to
the pool. This is a hypothesis until peak windows and both sides' ownership
are proved. It requires a common PPC/ARM lease, request identity, cancellation,
acknowledgement and reset handling. Serial FatFS service alone does not stop
PPC from overwriting an active buffer. No union or memory-map change has been
made merely on the basis of their usually separate UI flows.

The exact proposed shared extent is `0x33E000` (3,399,680 bytes). Keeping it
contiguous releases two discontiguous pieces (`0xC2000` and `0x13E000`), so
the pool would need four-bank support. Increasing the existing extra-bank
size would overlap live ghost inputs. Repacking would retain its separate
primary codec workspace and place a second `0x4E000` workspace in the shared
extent, leaving 3,080,192 bytes of candidate staging.

Lifetime audit found legitimate current overlaps: ghost background catalog
refresh can run during state I/O, RAM saves use staging without a storage
request, and deferred restores/TAS consumers keep pointers after `takeResult`.
Lease ownership must include local preparation and response consumption, not
only ARM busy time. Ghost service also needs a real reset/cancellation
retirement protocol before either side can reuse the shared bytes. These are
required integration changes, not optional defensive checks.

The executable lease protocol and exact call-site plan are in
`timewarp-transfer-lease.md`. Twelve native C tests cover delayed or stale
receipts, consumption after ACK, local RAM transactions, cancellation and
retirement of both workers on reset. Four cache lines (128 bytes) fit in the
existing ghost mailbox reservation: request/response bodies and separate
publication lines. A cache-line writeback is not atomic; publication withdraws
the old commit, flushes the new body, then commits with a fresh nonwrapping
generation. Seven adversarial publication tests cover torn lines, stale reads
and reinjection. Additional central bookkeeping is 68 PPC bytes including
tokens, 56 ARM bytes and 16 worker-retirement bytes, before adapter/code costs.

Production ARM worker retirement hooks are integrated, and PatchGame now
finishes outstanding DI work and its delayed completion before advancing
retirement. It returns to the kernel loop while draining and withholds the
PPC entry acknowledgement on failure. A fresh legacy mapping/capability must
be published before entry; the new PPC image must explicitly activate the
runtime ABI. The ARM coordinator and worker adapters now pass 104 focused
protocol, publication, retirement and existing-worker checks; the full launcher
rebuild passes with the reset barrier. PPC consumers are still being
integrated, so the reclaimed 2 MiB is not yet enabled in gameplay.

The optional further 448 KiB DI tail has a production reservation API, still
unwired. The sole DI reader processes a serial fence before narrowing scratch
from 512 KiB to 64 KiB; the limit never widens again during that kernel's
lifetime, including reinjection. Current code does not advertise or allocate
that tail. Reader traces, rounding/CISO cases and full-tail canaries pass;
hardware throughput and the runtime map handshake remain unproved. See
`timewarp-di-scratch-notes.md`.

The first online prototype also needs user-entered display names above remote

racing feasibility document for the recorded presentation requirements.

Cross-region racing is mandatory for that first prototype: PAL, JP and US must
share rooms, including PAL versus JP. PAL uses the runners' 60 Hz mode; slower
25 fps PAL support/testing is outside the first prototype's scope. Normalize scene identities and elapsed
time through read-only adapters while each player runs their native regional
game. Check the online protocol separately from game region; mixed-region
interoperability is not deferred to the four-player stretch goal.

| Feature | Required implementation/proof |
|---|---|
| Arbitrary-percent slowdown | Non-timer scheduler; correct input edges, quarterframes, retail pause/cutscene/transition/audio behavior; region checks. Existing practice hold alone does not slow every game subsystem. |
| Recorded ghost camera | Capture the actual render camera and projection; prove playback fidelity; versioned bounded tracks and old-reader compatibility. Scalar lower bound is 56 bytes/sample, final matrices 116. |
| Online downloads and uploads | Bounded authenticated service transport; strict independent file admission; explicit account/upload flow, cancellation and offline behavior. Existing public API evidence does not prove gameplay networking on Wii or standalone Dolphin. |
| IL boards and achievement percentages | Canonical rules/assistance identities, server validation and moderation, explicit participant population and versioned denominator. Download popularity is not verified competition. |
| Racing line and collision overlay | Bounded read-only rendering; actual Mario floor triangle/type; stage and owner lifetimes; no collision writes or fabricated full-geometry coverage. |
| Shareable states | Retain exact compatibility and live-owner checks; test independent boots/players/stage histories. Cross-region/build pointer relocation is a separate reconstruction problem. |
| Freecam keyframes | Explicit timeline identity, camera mode/cut/projection data and bounded playback ownership. |
| Branching TAS | Persist immutable branch A before takeover creates B; initially full small input tapes plus sparse large anchors; checked manifest publication, seeking, modal controls and preservation on failure. |
| Desync feedback | Continue diagnostic fingerprint warnings separately from hard structure/owner/file failures. A warning does not certify determinism or branch provenance. |
