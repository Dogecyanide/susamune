# Timewarp: immutable block pool and direct Quick producer

The promoted allocator accepts the encoder's separate eight-byte block header and payload directly. It hashes both pieces in stream order, checks complete bytes after a hash match, and copies only new blocks into owned pool or transaction storage. It needs no additional encoded-block buffer. The contiguous append API delegates to the same implementation. All old roots remain intact until a complete candidate passes validation and final bank placement; failure leaves an abortable candidate.

The four headers now live in `include/susamune`: `state_multibank_memory.h`, `state_chunk_pool.h`, `state_staged_transaction.h`, and `state_root_reader.h`. The old private paths are compatibility includes. `state_quick_producer.hxx` connects their guarded append path to `StateCodec::compressQuickBlocks`. These foundations do not activate the shared map or replace savestate consumers. The promotion receipt records the original private-header hashes and the unchanged historical receipts.

## Measured capacity and actual PPC execution

`scripts/timewarp_pool_ppc.py` runs the actual producer, allocator, and production decoder in an owned standalone Dolphin process. Its four discontiguous fake-VMEM banks use the proposed bank lengths and logical order. These test addresses are isolated from gameplay and do not prove the Wii mapping or ARM cache handoff.

| Three-state set | Occupied bytes, including directory and alignment | Free in four banks |
| --- | ---: | ---: |
| Noki 1 | 10,303,552 | 10,602,432 |
| Bianco 1 / Ricco 1 / Gelato 1 | 20,445,056 | 460,928 |

The PPC-produced encoded bytes equal the previously measured PPC streams exactly. Every state decoded correctly both with ordinary output and with a protected 31-byte output range. Noki 1 also fits the existing two-bank capacity, leaving 8,505,280 bytes. Its independent Quick streams would exceed the proposed four-bank capacity by 16,266 bytes before directory/alignment; the measured same-level sharing is substantial.

Actual PPC replacements in each of the three mixed-set slots passed candidate decode, abort with all old encoded roots unchanged, retry, commit, and final encoded-byte/decode checks. The staging peaks were 2,269,152, 2,207,520, and 2,269,152 bytes, within the 3,080,192-byte candidate allowance. The tightest final placement occupied 20,626,592 bytes, leaving 279,392. Commit moved 7,070,194–16,402,501 bytes depending on the replaced slot.

## Validation and cost limits

The promoted code passed 29 existing pool, staged-transaction, and reader guards plus six new direct-producer tests. Native replay covers 30 measured PPC streams, 84 successful split-parts replacements, 9,750 abort boundaries, and 906 ordinary/protected decoder checks. Native direct encoding committed 27 replacements. Three mixed-set replacements safely refused because native x64 LZ4 bytes differ from the PPC roots and cannot share them; actual PPC execution separately proves those target cases.

The existing 32 KiB directory budget is unchanged: the directory and reserved scratch end at byte 28,032, leaving 4,736 bytes. PPC compilation gives a 24-byte producer context and a 48-byte destination table. The largest individual emitted frame in the isolated `-Oz` producer compile is 208 bytes; that is not a bound on the whole nested call stack.

In one unlimited-speed Dolphin run, encoder plus append took approximately 0.109–0.130 seconds; transaction begin 0.005–0.038 seconds; commit 0.022–0.065 seconds; reader validation plus decoding 0.092–0.116 seconds. These host times include command polling and isolated fixture bookkeeping. They are not Wii timings, complete savestate latency, or a speedup claim. Full directory validation, encoded-byte hashing/CRC scans, and compaction remain measurable costs; the proof does not establish absence of a hot-load regression.

Canonical evidence is under `build/timewarp-pool-producer/{promotion.json,guards.json,producer-layout.json,validated/receipt.json}` and `build/timewarp-pool-ppc/windowed/receipt.json`. The first PPC fixture was preserved after its diagnostic output buffer proved too small for the 7,490,731-byte mixed third stream; the successful fixture exports bounded diagnostic windows. Both owned processes were stopped. No released fixture or timer source was changed.

Integration still needs exclusive transfer ownership through preparation, ARM completion, and all local consumers; immutable export and recovery handling; real game owner/output-range checks; reset retirement; and Wii timing/cache validation. Installing the new directory must happen before legacy RAM roots exist or through a separately proved migration. Worker quiescence alone does not make old RAM states disposable.
