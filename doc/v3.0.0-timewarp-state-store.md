# Mixed shared-state store

`StateStore` keeps shared Quick blocks and verbatim legacy Deflate streams in the same four-bank allocator. A descriptor's existing 16-bit kind word distinguishes Quick (0) from opaque Deflate (1); descriptor size and the 32 KiB directory budget do not grow. Opaque pieces contain at most 128 KiB, never cross a bank, and concatenate without a synthetic header. Their internal `rawBytes` field counts stored bytes. The adapter separately binds the real decoded size and Adler checksum. Quick keeps its canonical eight-byte frame and exact block sharing; kinds never share descriptors.

The PPC adapter context is 160 bytes. Its identities retain the caller's global `StoredState` generation, metadata tag, raw/packed sizes, Adler checksum, encoded CRC, and codec kind. Internal per-slot transaction generations remain independent. A retained repack may preserve its external generation while changing packed size, metadata tag, and encoded CRC. No adapter operation generates a replacement global identity.

Candidate admission never releases an old root. Direct Quick output appends separate borrowed header and payload pieces. Opaque imports append bounded borrowed pieces. Deflate compression/repack can first measure immutable input, reserve candidate-only pieces, then encode directly into at most six merged physical output spans. The normal codec and a second fixed repack workspace suffice. No whole-state buffer is added. Sealing validates zlib/Quick kind, exact stream CRC and complete production decoding before commit. Commit repeats final bank-aware placement and old-root checks; failure leaves an abortable candidate.

Pinned reads bind identity, internal generation, descriptor table, encoded CRC, and actual spans. Restore rejects all pool, staging, adapter and reader-table aliases. The existing production decoder and protected-output copy policy remain responsible for decoded output. `exportPlan` writes the version-2, 2,080-byte plan from a checked committed pin: Quick emits the existing frame, Deflate emits no prefix. The caller retains both the pin and transfer ownership through ARM completion and local consumption.

The 41-test allocator/reader/producer/store regression run passed. New guards cover mixed formats, distinct global/internal generations, abort at each opaque append, insufficient temporary/final capacity, post-seal corruption, stale pins, kind mutation, workspace/output aliases, split zlib headers, both export kinds, and actual production retained repacking. One former reserved-word negative test now uses unknown kind 2, since kind 1 is deliberately assigned to opaque data.

Fresh directory initialization requires empty current-session metadata and exclusive ownership of a new shared epoch; it never reinterprets a live legacy pool. Windowed import uses the disjoint transaction tail, while primary codec work uses its existing separate workspace. The tail is mutually exclusive with the second repack workspace. The timer source is untouched.

## Integrated consumers

The working source now routes RAM save, load and clear through the store after explicit shared-map activation. Retained repacks preserve their external generation and must reduce physical pool occupancy, including lost sharing. SD-to-slot imports append complete Quick blocks or bounded opaque pieces from the separate 319,488-byte tail, retaining STATE ownership across receipts and rereading incomplete Quick blocks. Old roots remain committed until full stream and metadata validation succeeds. Export retains a checked root pin through the planned ARM export's terminal receipt. Direct streamed SD restore pins an admitted recovery root through validation, writes and any rollback.

`TIMEWARP_SHARED_STORE` remains off by default. Emulator builds still use their legacy runtime mapping. Native manager, client and worker tests do not establish Wii cache behavior or a complete game restore. The frozen Wii Memory Probe 1 tests only the earlier cold-menu transport and legacy state pool.

## Bounded Quick replacement replay prototype

`TIMEWARP_QUICK_REPLAY` is off by default and requires the shared store. Its
RAM-only Wii caller uses `StateQuickReplay` to prepare every candidate block,
cache new encoded blocks in available pool/staging space, and keep a bounded
recipe for the remainder. The plan and exact-collision comparison scratch use
about 155 KiB of the existing mutually exclusive 319,488-byte transfer tail.
There is no new reservation or archive format.

Preparation preserves the three old roots and derives final reference counts
from the two surviving roots plus every candidate reference. Reused blocks
from the replaced root remain live. All matching encoded hashes receive exact
byte comparisons, including uncached candidate duplicates. Before reclaiming
anything, commit checks the token, identities, roots, plan, cached bytes and
final bank-aware destinations. It then moves retained/cached blocks downward
in source order, regenerates only spilled blocks, and publishes the new root.
There is no allocation, cancellation or fallible codec callback after the
destructive boundary. SD imports retain their existing fully staged path.

`StateCodec::prepareQuickSource` validates aliases, the zero interval and a
maximum of 256 blocks. `encodePreparedQuickBlock` resets LZ4 per block and
uses the existing full worst-case workspace with the non-limited compressor.
For an admitted immutable source and valid block index, its encoder path has
no failure branch. Prepared/source descriptors and the callback context must
also remain immutable, and all addresses must use canonical PPC aliases.
Two new focused checks verify selective out-of-order replay against ordinary
Quick bytes and refusal before writes for invalid admission.

Six focused native planner tests cover each slot in a full pool with no
candidate staging, shared references, bank boundaries, actual hash collisions,
exact candidate duplicates, cached-data/identity/plan/root corruption, busy or
cancelled plans, and retained Deflate roots. Successful replacements preserve
exact encoded roots and pass protected decoding. These tests do not establish
gameplay, PowerPC execution or Wii latency.

The opt-in caller has source-stability admission and aligned cache preparation
as described in [the hardware source audit](timewarp-replay-source-stability.md).
It retains the ordinary append path when replay is not admitted. A fitting
cached candidate needs one compression pass; overflowing candidates regenerate
only spilled blocks, potentially approaching another full pass. This addresses
the temporary-space design but does not yet prove existing slot-1/2 latency,
long-recording capacity or the complete three-fast-slot target.

`build/timewarp-replay-ppc-1/receipt.json` now exercises the concrete worst
captured staging deficit on actual PowerPC instructions in an owned isolated
Dolphin process. The canonical Bianco 1 / Noki 1 / Gelato 1 roots use
20,566,912 bytes. Replacing slot 1 with Bianco 5/slot3 previously required
5,961,024 temporary bytes, 2,880,832 beyond available staging. The new path

64 of 115 blocks (8,332,024 raw bytes), and uses 158,432 bytes of tail scratch.
The final roots occupy 20,257,952 bytes, leaving 648,032. It preserves every
old encoded root before commit, matches every final encoded root and protected

This is an immutable-captured-input algorithm test with synthetic admission,
not a gameplay lifecycle or Wii timing measurement. It also moves 17,192,965
bytes during compaction; that cost and partial re-encoding must be included
when measuring the first-Mario-visible user timing endpoint on hardware.
